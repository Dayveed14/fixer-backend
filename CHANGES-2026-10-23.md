# Fixer backend — changes (23 Oct 2026)

**Before deploying:** back up, then run `migrations/2026-10-23d_sessions_passwords.sql`.
The code also works before the migration (sessions fall back to role checks),
so order isn't critical. Change Render's start command to `npm start` if it's
set to anything else — `start` is now `node app.js` (nodemon is dev-only).
New optional env vars: `CONTACT_EMAIL_TO` (contact form; was already needed),
`ALERT_WEBHOOK_URL`, `DB_SSL` — see `.env.example`.

## P0 — payments
- **Fixed: a customer could pay an outdated (cheaper) repair quote.** If the admin
  re-sent a quote while the customer was paying, the old payment was accepted.
  Payments are now bound to the quote amount and re-checked under the row lock.
- Payment mismatches and paid-but-unapplied payments raise alerts.
- Reviewed and re-verified on a real database: server-side pricing, Paystack
  verification (amount, currency, owner, slot/zone/details), one payment → one
  record (10 simultaneous submissions → 1 booking), webhook signature and
  idempotency (8 parallel replays → 1 change), webhook racing the customer,
  rollback when creating the record fails.

## P0 — authentication and authorization (every privileged endpoint audited)
- Sessions can now be revoked: password change signs out other devices; a
  deleted account or changed role ends sessions immediately. JWT algorithm pinned
  to HS256; dead cookies are cleared; database outage → 503 (not a logout).
- **New:** `PATCH /api/users/me/password` for all roles (current password,
  8–72 chars, security email, rate limited).
- Login no longer reveals which emails have accounts (same message and timing);
  rejects non-string input.
- Registration and admin-created accounts validate email, password and lengths.
- Technician list: non-admins get names only (emails/phones were exposed to every user).
- Customer dashboard stats: self or admin only (technicians could read anyone's).
- Devices: only the owner or an admin can edit/delete (technicians could delete any device).
- `?limit=` capped everywhere (tickets, bookings, devices, notifications).
- Tickets: priority/status validated on create.
- Articles/videos: author taken from the session (was trusted from the form),
  title/slug/status validated, duplicate slug → 409, rejected uploads deleted from Cloudinary.
- Contact form: HTML escaped (was injectable into the support inbox), reply-to
  email validated, subject can't inject headers, lengths capped.
- Uploads: exact extension + MIME pairs, SVG refused, images max 10 MB on the
  article route, videos only on the video route; upload errors → 400/413.
- **New admin endpoints:** `GET/PATCH/DELETE /api/users/:id` (customers and
  technicians only; delete refused when the account has bookings/repairs/payments).
  The admin Users/Technicians pages already called these and failed.
- CSRF: the client header is now also required on browser requests without a
  cookie (closes "login CSRF"); the Paystack webhook is exempt.

## P0 — transactions and concurrency (new real-database tests)
- `npm run test:integration` (48 tests) on MySQL/MariaDB: concurrent bookings and
  pickups, webhook races, rollbacks, five admins moving the same shipment, approve

  every dashboard query, sessions/password change, admin user management.
